# NE-11E3: Release path sanitization

The baseline scanner flagged 24 files. Twenty-one contained machine-specific workspace prefixes in historical database locations or commands; these prefixes were changed to repository-relative paths. The other three were false positives: `/home/bookDetails` is part of an HTTPS scholarly source URL, including in a source lock and staged evidence. Those source URLs remain intact. The scanner now distinguishes an HTTP URL's path from a local home path, with regression checks for Unix and Windows machine paths and a local path following a URL. The original list of affected files is in [the NE-11D integrity report](../ne11d/03-integrity-and-regression.md); the diff identifies each normalized field and line.

Before: sanitizer failed with 24 affected files. After: sanitizer and G4A isolation tests passed (6 tests); sanitizer, source-lock, schema, and coverage-audit tests passed (95 tests). All 16 changed JSON files parse. The local-path JSON values identify generated database locations, not source identities. Searches for the original SHA-256 values of the 15 modified candidate JSON artifacts found no recorded references in documentation, audit data, tests, or tools. No CKL object, source lock, source URL, evidence, or attested measurement was changed. Risk: historical paths are now portable representations, so their original machine-specific prefixes are no longer present in the working tree; Git retains the original history.
