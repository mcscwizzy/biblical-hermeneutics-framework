## Implemented retrieval corrections

- Query normalization now excludes common auxiliary terms including `have`, `at`, and `mean`; query-analysis tests protect the extracted terms.
- The index retains term groups per claim and evidence item. It excludes rationale, caveat, reference, and interpretive-note text from coherent-evidence matching so a phrase in a separate note cannot manufacture a passage-level match.
- A claim/evidence match covering at least 75% of substantive query terms contributes four raw points per covered term, capped at 16. Debug results identify the matched terms, source field, unit ID, and coverage. This resolves the close one-body ranking using the 1 Cor 12 evidence unit; it does not add a book or query-specific preference.
- Direct candidates now sort before related-result expansion. The regression query “What does Paul mean by judging nothing before the time?” previously let the related `who-was-paul` title match outrank direct 1 Corinthians evidence. With the direct-source key first, `1-corinthians` leads. The explicit passage note says “Judging nothing before the time cautions premature final verdicts”; the related person result matched only “Paul.”
- For a query that explicitly names a book and chapter, a place result is demoted only when it both cites that chapter and has a title or alias that closely resembles the named book. This resolves the `philippi`/`philippians` collision for the explicit Philippians 1:27 query without imposing book-first ordering on other passage-specific or cross-text questions. Implicit topical queries do not receive a book preference.
- First Corinthians test assertions now follow the evidence and query scope: the implicit weaker-members/conscience query requires the book within five, the Corinthian meal query requires its focused meal source first, and the one-body query requires the 1 Cor 12 source first without an invented book-first requirement. Explicit book-only questions retain the existing book preference.

No relevance threshold was lowered, and no expected score minimum was reduced. The six failures were in service-level indexing, scoring, ordering, and pruning; they did not justify changing SQLite search. JSON and SQLite lookup parity and the Abram → Abraham alias tests pass, as do precision, claim-level, query-analysis, and source-integrity gates; their final counts are in the consolidated final-gate report.
