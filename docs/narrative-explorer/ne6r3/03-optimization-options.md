# NE-6R3 — Optimization Options and Risk

Audit date: 2026-10-16  
Starting commit: `cb1be01559a4d56a1858ee8807d6b34eb989a9a7`

## Finding

No packaging reduction was implemented in this audit. The measured reduction
is **0 bytes**. The deployment artifact itself could not be retrieved, so
there is no supported evidence for claiming a bundle-size improvement.

The successful build-hook index is 116,334,592 bytes and is required by the
read-only CKL repository. Required tracked resources contribute another
80,074,267 bytes before runtime dependencies and generated bytecode. The
deployment log reports 317.82 MB after Vercel optimization, against its
explicit 225 MB limit. Any optimization intended to fit that limit must save
at least 92.82 MB, plus reasonable headroom. The exact rounded deployment
measurements and local input accounting are in `01-bundle-size-inventory.md`.

### A. Build and development artifacts

The exact `.vercelignore` simulation removed 18,549 files and 514,643,805
bytes from the tracked tree, matching Vercel's log count. These are already
excluded on the failing deployment, so they cannot be credited as new savings.
The remaining source tree does contain retained `tools/` and `examples/`
files, but the failed function trace was unavailable to show whether they are
actually packaged. Removing them globally or excluding them from the function
without trace evidence is not justified by the current measurements.

### B. Identical copies and package-data overlap

Content hashing found 25 duplicate groups (151,625 bytes in extra copies).
Many are the same geography/journey JSON served under both `/frontend` and
`/static`; both mounts exist. The duplicated icon image files are separate
browser-icon URLs. None is safe to remove while preserving current routes.

Setuptools package-data matches 73,566,139 bytes already present in source.
That is configuration overlap, not proof that Vercel stores a second copy.
The failed deployment did not expose the install/build tree needed to measure
copies. The CKL SQLite file and 687 source JSON files are distinct runtime
roles and both remain required.

### C. CKL inclusion and identity

`includeFiles: "framework/canonical_library/**"` is broad. It currently
ensures the function can resolve the generated database and CKL source files
that support source-identity and stale-index verification. The `.vercelignore`
rule already removes `.bhf-data/**`; the `excludeFiles` rule for a child of
that directory is therefore overlapping. Removing that redundant rule would
have no measured size impact and is not needed for this audit.

Before narrowing the CKL include set, a candidate build must show the exact
retained paths and pass the full source-inventory fingerprint, source-manifest
fingerprint, integrity check, retrieval parity, and API parity checks. This
audit makes no include/exclude change.

### D. Dependencies

The local Python 3.12 dependency closure for the four declared base
dependencies is 16,000,116 bytes across 15 distributions. This is not a
deployment measurement; the Vercel resolver versions and bundler output may
differ. No dependency is proven removable. Analyzer output should identify
package names, paths, and bytes before considering any dependency packaging
change. Existing package requirements for Maps, archaeology, lexical,
Commentary, and reader routes remain intact.

### E. SQLite

The rebuilt index has no free pages and passes `PRAGMA integrity_check`.
Its local dbstat allocation is 55,439,360 table bytes and 60,866,560 index
bytes. The existing `idx_keywords_term` appears redundant with a leftmost
primary-key prefix but is declared required and may affect retrieval
performance. A local measurement of its allocated pages is not proof it can
be dropped while preserving query plans, response latency, or schema checks.
Even that hypothetical 7,593,984-byte removal is insufficient for the current
92.82 MB gap. No index construction or retrieval change was made.

### Decision

Keep all CKL evidence, source objects, database schema/indexes, Commentary,
translations, lexical database, geography assets, offline/static assets, and
reader routes. The size failure should next be investigated through an
authorized Preview-only Large Functions build, which can test the same
verified payload under a supported larger limit and emit bundle diagnostics.
If that option is unavailable, create a separate architecture proposal rather
than removing required resources in this transaction.
