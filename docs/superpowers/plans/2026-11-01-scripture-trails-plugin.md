# Scripture Trails Plugin Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a deterministic, validated, standalone Scripture Trails skills-only plugin ZIP from selected BHF modules.

**Architecture:** Reuse `bhf_lib` to load and resolve the configured BHF modules. Generate themed references and a source hash manifest into the plugin workspace, then package only explicit runtime files with reproducible ZIP metadata. Validate the plugin format, generated drift, archive contents, and the conversational acceptance corpus without claiming model-based results.

**Tech Stack:** Python 3.9+, existing PyYAML, stdlib `zipfile`/`hashlib`/`json`/`argparse`, pytest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-01-scripture-trails-design.md` and the Scripture Trails task brief.

## Global Constraints

- The plugin requires no BHF API, website, account, backend, MCP server, credentials, database, or external service.
- Always include the seven foundational modules: `core.core-framework`, `core.genre-awareness`, `core.original-audience`, `core.observe-interpret-apply`, `core.intertextuality`, `core.epistemic-humility`, and `core.anti-hallucination`.
- Do not package CKL data, Narrative Explorer state, Tyndale datasets, Bible translation datasets, or developer test fixtures.
- Preserve CC BY 4.0 attribution and provenance; do not alter source modules.
- Do not change BHF application behavior, routes, data, deployments, or existing CI gates.
- Keep build outputs deterministic and distinguish automated checks from live model evaluations.

## Review Focus

- Missing dependency or newly changed selected module metadata; validate source resolution and report affected references.
- BHF internal references that cannot resolve; fail validation before generation.
- ZIP path traversal or accidentally included test/research data; package by allowlist and validate every archive member.
- Stale committed references after source or generator changes; compare generated bytes in `--check` mode.
- Claims that static checks prove conversational behavior; label model acceptance cases as manual.
