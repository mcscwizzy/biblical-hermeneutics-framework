# BHF UI-05 — Failure Classification

The baseline reproduction was performed on the untouched UI-03 master SHA `c44c19a708f1073e1af815a477f8c9b6701bd4ea`. Each case was run independently with a fresh GUI app fixture and browser. The ten failures below predate UI-04, but were investigated as unresolved acceptance defects rather than presumed harmless.

| Test | Original failure signature and browser observation | Expected behavior | Root cause | Classification | Remediation |
|---|---|---|---|---|---|
| `tests/gui/test_canonical_browser.py::test_canonical_browser_opens_editor_for_draft_object` | Selenium raised `StaleElementReferenceException` from `BasePage.click` while using the canonical result button after scrolling; the detail/editor navigation did not complete. With the click helper corrected, saving against the full 695-record library invalidated the cache and its redirect reload exceeded the browser's 20-second renderer wait. | Open a draft object's editor and save the edited draft through the UI. | The test helper retained a WebElement across a scroll-triggered rerender; the browser test then used a full production-sized library for a one-record editor contract, making the reload path too slow for this test fixture. | Selenium helper defect plus test-fixture lifecycle/performance problem; no editor product defect found. | Re-query and click the current visible result button; run this editor journey against a private one-record synthetic CKL fixture. Keep editor/save assertions. |
| `tests/gui/test_mobile_layout.py::test_mobile_passage_heading_updates_with_translation_badge` | Assertion expected `.reader-translation-badge` to be `ASV`; the browser displayed `KJV` before and after passage navigation. | Passage heading and badge stay aligned with the selected translation. | The test hardcoded an obsolete translation default; the configured reader default is KJV. | Stale test expectation. | Capture the currently selected abbreviation and assert it remains the badge through book/chapter navigation. |
| `tests/gui/test_mobile_layout.py::test_mobile_ask_submit_still_works` | Wait/click targeted the removed `[data-passage-action="ask"]` control and retired embedded Ask answer flow. The current mobile reader has no such passage action. | Ask BHF carries the exact current selection and question into the configured external-assistant handoff. | The test still described the retired in-workspace Ask UI. The approved interaction is the Ask BHF modal launched from Companion, with a prepared prompt and copy/open handoff. | Stale test expectation. | Exercise the current mobile modal, selected verse, prepared prompt, copy action, and assistant destination. Stub browser clipboard/window APIs so no external request is sent. |
| `tests/gui/test_reader.py::test_clicking_verse_number_selects_entire_verse` | The verse became selected, but the assertion queried retired `.ask-form` fields for start/end/text and failed because those fields no longer exist. Shared selection state contained John 1:1. | Clicking verse number selects that complete verse in the shared reader selection. | The test inspected the former Ask form rather than the current shared selection API. | Stale test expectation. | Assert book, chapter, verse-level selection, selected verse list, and selected text through `window.BHFStudySelection.getState()`. |
| `tests/gui/test_reader.py::test_import_dialog_uses_user_supplied_translation_name` | Supplied name assertion passed; a later assertion expected the selected translation to be ASV, while the browser kept KJV selected. | Import dialog retains the user-supplied name and does not silently change the active reader translation. | The test hardcoded the obsolete ASV default. | Stale test expectation. | Capture the selected translation before opening import and assert it remains selected afterward. |
| `tests/gui/test_study_companion.py::test_native_resource_never_renders_previous_selection_context` | The test waited on retired `/api/study/companion-context` data and `[data-companion-resource-host]`; the current browser opened the native Map panel for John 1:5. Its assertion did not exercise the actual map request lifecycle. | A late response for an earlier selected passage must not replace the currently selected passage's resource details. | The test targeted the removed Companion context API. Replacing it with a deterministic race against the live map endpoints exposed that `openMapPanel` accepted late responses from earlier opens. | Stale test target and genuine application race defect. | Add a monotonically increasing map-open request ID and ignore stale catalog/data results and errors; test delayed John 1:4 responses against a completed John 1:5 open. |
| `tests/gui/test_study_companion.py::test_word_study_choice_updates_and_restores_shared_selection` | Timed out waiting for `[data-word-study-position]`; browser remained on “Loading deterministic word study…” while the action tried to load CKL. | Display deterministic lexical choices and let the user update/restore the shared selection. | Word Study uses the separate lexical SQLite service, but the study action first loaded the full CKL. The cold 695-record CKL path exceeded the GUI wait although lexical data was available. | Genuine application performance defect. | Skip unrelated CKL retrieval for `word_study`; count complete/ambiguous lexical evidence in confidence without adding fake CKL object IDs. |
| `tests/gui/test_workspace_panels.py::test_workspace_tabs_switch` | Assertion expected `#workspace-pane-ask`; the browser showed the Ask BHF modal with the current John 1 passage, and no Ask workspace pane exists. | Workspace tabs switch among current study resources; Ask BHF opens its passage-aware external handoff modal. | Test expected the retired Ask workspace tab. | Stale test expectation. | Assert the modal, passage context, and absence of an Ask pane; close it, then retain the notes/highlights/saved/explore switching assertions. |
| `tests/gui/test_workspace_panels.py::test_desktop_primary_navigation_preserves_reader_split` | Assertion expected the retired Ask workspace tab; the actual modal was visible and the reader/Companion split remained intact. | Primary navigation and Ask BHF preserve the desktop reader split. | Test expected Ask as a workspace tab rather than a modal handoff. | Stale test expectation. | Assert the modal and passage context, verify the split, close the modal, and continue the existing primary-navigation journey. |
| `tests/gui/test_workspace_panels.py::test_context_result_header_keeps_title_readable_in_study_panel` | JavaScript threw `TypeError` when assigning to `innerHTML` on null `[data-testid="answer-output"]`. The embedded Ask answer host was removed. | A deterministic study result title remains readable in the study panel. | The visual test mounted content into the retired Ask output selector instead of rendering a current deterministic result. | Stale test setup/target. | Open the current Word Study result and measure its real `.answer-header` in `#lexicon-panel`; retain the title and eyebrow layout assertions. |

The maps case is mixed: the baseline test itself no longer represented the native resource contract, but an accurate replacement test demonstrated and now guards a real stale-response defect. The classification does not treat baseline age as evidence that any case is safe to ignore.
