# Reader Pilot Readiness

## Judgment

**Pilot preparation: READY WITH CONDITIONS.** The protocol, privacy workflow,
task bank, validator, aggregate analyzer, and bounded browser acceptance are
prepared. A maintainer must recruit 6–8 consenting adults, confirm the local
store is restricted and ignored, and run the sessions before reporting reader
findings.

**Actual reader study: AWAITING PARTICIPANTS.** No authentic participant data
was present in the authorized local input directory at baseline. No human
findings are reported.

## Task execution coverage

The nine fixed-passage journeys and the participant-selected familiar-passage
task are represented in the ED-5 scripted evaluator and/or existing focused
reader tests. ED-6 reruns Chromium connectivity, ED-5 mobile acceptance, and
focused journeys for source disclosure, review labels, disputes, verified
relationship direction and return, completed-empty state, 390px operation, and
keyboard interaction. See [validation results](validation-results.md) for the
commands and exact outcomes.

The familiar-passage task necessarily lets the participant choose an eligible
passage; the facilitator should not substitute an answer if their selected
passage has no BHF material. The negative 1 Kings 2 task explains only current
BHF coverage. Natural-language search task 1 John uses the Context workspace
and has a live browser acceptance check. The shorter question used in the
ED-5 scripted retrieval evaluator did not return 1 John in the generic browser
search, so the task uses a passage-grounded natural-language question. This
is a deterministic reader-path observation and task wording adjustment, not
participant feedback; the actual task remains participant-observed.

No production navigation changes were made solely to anticipate participant
preferences. If a browser check reveals a blocker, record the exact failure and
repair only that demonstrated blocker before recruitment.

## Conditions before first session

- Read the [protocol](participant-protocol.md), [consent script](consent-and-privacy.md),
  and [facilitator guide](facilitator-guide.md).
- Arrange broad, voluntary recruitment; include mobile use where feasible.
- Set the destination and retention plan for private notes and any aggregate
  report. Keep real records under the ignored `.bhf-data/ed6-reader-pilot/`.
- Confirm browser/network access on the device used for the session. Do not
  use a participant account or enable analytics or recording.
- Use a new anonymous code only after consent; do not store a code-to-name key
  in the dataset or repository.
- Check the live [task bank](study-task-bank.md) against current passage
  availability before the session and preserve the assignment if an unexpected
  issue arises; record the issue rather than altering scholarly content.

## Scope limit

This is a small, exploratory convenience sample. It can reveal reproducible
usability barriers and evidence-literacy questions in the sessions observed.
It cannot establish population-wide usefulness, spiritual outcomes, or
scholarly correctness. Scholarly review remains separately pending.
