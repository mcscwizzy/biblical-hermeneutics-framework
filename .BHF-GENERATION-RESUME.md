## How It Works

### Phase 1: Evidence Bundling
```
Canonical Chapter (Genesis 1)
    ↓
Evidence Bundle (deterministic hash)
    - Scripture text
    - People, places, events (minimal: expandable)
    - Archaeology, geography, cultural context (structured)
    - Historical/chronological references
    - Linguistic data where available
```

### Phase 2: Generation
```
Evidence Bundle + Canonical Text + System Prompt
    ↓
AI Model (Haiku, Opus, or configured model)
    - Evidence-grounded writing
    - JSON response with sections, blocks
    - Each block cites evidence IDs
    ↓
Raw JSON Response
```

### Phase 3: Validation
```
Generated JSON
    ↓
Strict Block-Level Validation
    - Evidence exists in bundle ✓
    - Confidence ≤ evidence confidence ✓
    - Disputed evidence not "fact" ✓
    - Dates from evidence only ✓
    - No invented claims ✓
    ↓
Partial Salvage: Keep good sections, drop bad ones
    - Status: VALIDATED, PARTIAL, NEEDS_REVIEW, or FAILED
```

### Phase 4: Storage & Resumption
```
Commentary JSON → .bhf-data/bhf-commentary/{book}_{ch:03d}.json
Progress JSON → .bhf-data/bhf-commentary/.bhf-commentary-progress.json

Next session detects progress, resumes from next unfinished chapter.
```

## Model Configuration

Generation uses the configured model. Set via environment variables or config file:

```bash
# OpenRouter (recommended for scale)
export BHF_ADAPTER=openrouter
export BHF_API_KEY=your_api_key
export BHF_MODEL=anthropic/claude-haiku-4.5

# Local OpenAI-compatible (Ollama, vLLM, etc.)
export BHF_ADAPTER=openai_compatible
export BHF_BASE_URL=http://localhost:8000
export BHF_MODEL=your-model-name

# Ollama
export BHF_ADAPTER=ollama
export BHF_BASE_URL=http://localhost:11434
export BHF_MODEL=neural-chat
```

Default: Uses `BHF_ADAPTER` from `bhf_agent/config.py` (typically openrouter or configured default).

## What NOT to Do

❌ Don't manually edit JSON files (breaks evidence chain)
❌ Don't mix multiple generation sessions to same directory (progress file conflict)
❌ Don't force-regenerate unless evidence actually changed
❌ Don't use old progress files (incompatible schemas)
❌ Don't try to parallelize without file locking (risk data corruption)

## Validation & Quality

**Strict Validation Ensures**:
- ✓ Evidence IDs exist
- ✓ Confidence respects source evidence
- ✓ Disputed evidence never marked "fact"
- ✓ No made-up dates, places, people

## Troubleshooting

| Issue | Solution |
|-------|----------|
| `ImportError: adapters` | Check BHF_ADAPTER is set or run with correct config |
| `Model call failed` | Check API key, base URL, model name, internet connection |
| `JSON parse error` | Model returned non-JSON; check model instruction following |
| `Evidence not found` | Validation working correctly; block rejected as expected |
| `Progress file corrupted` | Delete `.bhf-commentary-progress.json`, restart (rescan everything) |
| `Out of memory` | Not expected (per-chapter load is small); check other processes |
