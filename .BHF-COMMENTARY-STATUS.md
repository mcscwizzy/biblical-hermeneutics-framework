**PHASE 4: Generation Contract**
- `prompts.py`: System and user prompts for evidence-grounded commentary
- Model instructions enforce BHF principles (evidence-only, no invention)

**PHASE 5: Strict Validation with Partial Salvage**
- `validation.py`: Block-level validation with rejection codes
- Checks: evidence existence, confidence limits, disputed handling, length
- Partial sections salvaged when some blocks fail

- CLI: `python -m bhf_agent.chapter_commentary build --all`

**PHASE 7: API Read Path**

## Storage & Architecture

**Storage**: JSON files per chapter
- Path: `.bhf-data/bhf-commentary/{book}_{chapter:03d}.json`
- Includes: reference, book, chapter, status, sections, metadata, errors
- Atomic writes prevent partial files
- All sections/blocks carry evidence IDs for audit trail

**Progress Tracking**
- `.bhf-data/bhf-commentary/.bhf-commentary-progress.json`
- Tracks: total, validated, partial, needs_review, failed, stale, pending
- Persisted after every 10 chapters during build_all

**Canonical Chapters**
- Discovered from Bible data: 1,189 total chapters
- Books: Genesis through Revelation, canonical order
- Includes all deuterocanonical where applicable

## Known Limitations

1. **Placeholder Evidence Bundling**: Current `evidence_bundling.py` creates minimal bundles.
   - Real implementation requires integrating with CKL/retrieval systems
   - Should pull actual archaeological, historical, linguistic evidence
   - Currently shows structure; evidence source TBD

2. **Model Integration**: Generator calls configured model via adapters.
   - Works with OpenRouter, local, OpenAI-compatible endpoints
   - Set via `BHF_ADAPTER`, `BHF_MODEL`, etc. in config
   - Prompt designed for evidence-grounded generation

3. **No UI Frontend Yet**
   - API endpoint ready but no reader panel integration
   - Ready for implementation alongside existing Tyndale panel

4. **No Parallelization Yet**
   - Single-threaded generation to keep indexing safe
   - Could add worker pool if careful with file locks
   - Current approach: one session, resumable progress

- `BHF_MODEL`: Model name (haiku-4.5, gpt-4, etc.)
